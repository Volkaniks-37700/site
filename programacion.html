01

Estructura de un OpMode

En FTC existen dos tipos de OpModes: LinearOpMode y OpMode. Ambos controlan el robot, pero funcionan de manera diferente.

📏

LinearOpMode Secuencial

El robot ejecuta las instrucciones línea por línea, de arriba hacia abajo. Es ideal para autónomos porque el flujo es fácil de seguir.

MiAutonomo.java
@Autonomous(name = "MiAutonomo") public class MiAutonomo extends LinearOpMode { @Override public void runOpMode() { // Inicialización initHardware(); waitForStart(); // Espera el START // Se ejecuta secuencialmente driveForward(0.5, 2000); // 2 seg turnRight(0.5, 1000); // 1 seg stopMotors(); } }

📖 Doc oficial: Crear un OpMode →

🔄

OpMode Usamos este

Es un modelo iterativo: el método loop() se repite continuamente hasta que el robot se detiene. Es el que nuestro equipo utiliza actualmente.

MiTeleOp.java
@TeleOp(name = "MiTeleOp") public class MiTeleOp extends OpMode { @Override public void init() { // Se ejecuta una vez al presionar INIT initHardware(); } @Override public void init_loop() { // Se repite mientras espera START } @Override public void start() { // Se ejecuta una vez al presionar START } @Override public void loop() { // Se repite continuamente readGamepad(); updateMotors(); } @Override public void stop() { // Se ejecuta al detener el robot } }

Comparativa rápida

CaracterísticaLinearOpModeOpMode (Iterativo)
FlujoSecuencial (línea por línea)Iterativo (loop continuo)
Método principalrunOpMode()init(), loop(), start(), stop()
Ideal paraAutónomos con secuencias clarasTeleOp y control en tiempo real
ComplejidadMás fácil de leer para principiantesMás flexible para lógica compleja

02

Formas de Tracción

La tracción define cómo se mueve tu robot. Cada tipo tiene ventajas y desventajas, y su programación cambia según la configuración de las llantas.

Tank Drive Recomendado para empezar

Es la tracción más simple y directa. Dos lados (izquierdo y derecho) con ruedas de tracción. Cada stick del gamepad controla un lado del robot.

  • 👍
    Fácil de programarMapeo directo de joystick a motor, sin matemáticas complejas.
  • 🔄
    Giros precisosIdeal para giros sobre el propio eje.
  • ⬆️
    Buena fuerza de empujeExcelente para empujar o subir rampas.
  • ⚠️
    No puede desplazarse de ladoRequiere girar para cambiar de dirección.
TankDrive.java
@TeleOp(name = "TankDrive") public class TankDrive extends OpMode { private DcMotor leftMotor, rightMotor; @Override public void init() { leftMotor = hardwareMap.get(DcMotor.class, "leftMotor"); rightMotor = hardwareMap.get(DcMotor.class, "rightMotor"); leftMotor.setDirection(DcMotor.Direction.REVERSE); } @Override public void loop() { double leftPower = -gamepad1.left_stick_y; double rightPower = -gamepad1.right_stick_y; leftMotor.setPower(leftPower); rightMotor.setPower(rightPower); } }

Arcade Drive Un solo joystick

Usa un solo joystick para controlar tanto el avance como el giro. El eje Y controla la velocidad y el eje X la dirección.

  • 🕹️
    Control intuitivoUn solo stick para todo el movimiento.
  • ⚡
    Fácil de aprenderIdeal para nuevos conductores.
  • ⚠️
    Menos control finoNo permite combinar avance y giro de forma independiente.
ArcadeDrive.java
@TeleOp(name = "ArcadeDrive") public class ArcadeDrive extends OpMode { private DcMotor leftMotor, rightMotor; @Override public void init() { leftMotor = hardwareMap.get(DcMotor.class, "leftMotor"); rightMotor = hardwareMap.get(DcMotor.class, "rightMotor"); leftMotor.setDirection(DcMotor.Direction.REVERSE); } @Override public void loop() { double forward = -gamepad1.left_stick_y; double turn = gamepad1.right_stick_x; leftMotor.setPower(forward + turn); rightMotor.setPower(forward - turn); } }

Mecanum Drive Nuestra configuración

Usa 4 llantas mecanum con rodillos a 45°. Permite movimiento omnidireccional: avanzar, retroceder, girar y desplazarse lateralmente sin cambiar la orientación.

  • ↔️
    Strafe (desplazamiento lateral)Moverse de lado sin girar. Ventaja competitiva enorme.
  • 🎯
    Máxima movilidadPuede apuntar y moverse en cualquier dirección.
  • ⚠️
    Menos fuerza de empujeLos rodillos reducen la tracción directa.
  • ⚠️
    Más complejo de programarRequiere combinar las 4 ruedas con suma y resta.
MecanumDrive.java
@TeleOp(name = "MecanumDrive") public class MecanumDrive extends OpMode { private DcMotor leftFront, rightFront, leftBack, rightBack; @Override public void init() { leftFront = hardwareMap.get(DcMotor.class, "leftFront"); rightFront = hardwareMap.get(DcMotor.class, "rightFront"); leftBack = hardwareMap.get(DcMotor.class, "leftBack"); rightBack = hardwareMap.get(DcMotor.class, "rightBack"); leftFront.setDirection(DcMotor.Direction.REVERSE); leftBack.setDirection(DcMotor.Direction.REVERSE); } @Override public void loop() { double forward = -gamepad1.left_stick_y; double strafe = gamepad1.left_stick_x; double rotate = gamepad1.right_stick_x; leftFront.setPower(forward + strafe + rotate); rightFront.setPower(forward - strafe - rotate); leftBack.setPower(forward - strafe + rotate); rightBack.setPower(forward + strafe - rotate); } }

03

Control Hub y Driver Station

El Control Hub es el cerebro del robot. La Driver Station es el control remoto. Aquí aprenderás a configurarlos y a subir tu código.

🧠

¿Qué es el Control Hub?

Es el dispositivo que ejecuta tu código. Contiene el Robot Controller (la app que corre tus OpModes) y todos los puertos donde se conectan motores, servos y sensores.

  • Puertos de motor: 0 a 3 (integrados) + expansión.
  • Puertos de servo: 0 a 5 (integrados) + expansión.
  • Puertos I2C: Para sensores de color, distancia, IMU, etc.
  • Puerto USB: Para cámaras o dispositivos externos.
  • IMU integrada: Giroscopio, acelerómetro y magnetómetro.
📱

¿Qué es la Driver Station?

Es el dispositivo desde el que controlas el robot. Generalmente es un Driver Hub o un celular Android con la app de Driver Station.

  • Se conecta por Wi-Fi al Control Hub.
  • Desde aquí seleccionas el OpMode a ejecutar.
  • Desde aquí configuras los puertos de cada motor y servo.
  • Muestra la telemetría en tiempo real.

🔌 Cómo configurar los puertos desde la Driver Station

1️⃣

Paso 1: Conectar el Driver Station

Enciende el Control Hub y conecta la Driver Station a su red Wi-Fi. Abre la app de Driver Station.

2️⃣

Paso 2: Abrir la configuración

En la Driver Station, toca los tres puntos verticales en la esquina superior derecha y selecciona "Configure Robot".

3️⃣

Paso 3: Crear o editar una configuración

Selecciona una configuración existente o crea una nueva. Aquí verás los puertos disponibles.

4️⃣

Paso 4: Asignar nombres y puertos

Para cada motor o servo, asigna un nombre (ej. "leftFront") y selecciona el puerto donde está conectado. Este nombre es el que usarás en tu código con hardwareMap.

⬆️ Cómo subir tu código al Control Hub

🖥️

Opción 1: Android Studio (recomendado)

Conecta el Control Hub a tu computadora por USB. En Android Studio, selecciona Build → Make Project y luego Run → Run 'TeamCode'. El código se compila y se instala automáticamente en el Control Hub.

📶

Opción 2: OnBot Java (inalámbrico)

Conéctate a la red Wi-Fi del Control Hub y abre un navegador en 192.168.43.1:8080. Desde ahí puedes escribir y compilar código directamente en el Control Hub, sin necesidad de Android Studio.

📊 La Telemetría: Tus ojos dentro del robot

La telemetría es la forma en que tu programa "habla" contigo durante la ejecución. Sin ella, programar un robot es como conducir con los ojos vendados: no sabes qué está pasando. telemetry.addData() te permite enviar datos a la Driver Station para verlos en tiempo real.

TelemetriaEjemplo.java
// En tu loop() o runOpMode() telemetry.addData("Potencia Motor Izq", leftMotor.getPower()); telemetry.addData("Posición Encoder", leftMotor.getCurrentPosition()); telemetry.addData("Estado", "Ejecutando"); telemetry.update(); // ¡No olvides esto! Sin update, no se muestra nada.
04

Tu primer Autónomo

Un autónomo básico no necesita encoders ni sensores. Puedes hacer que el robot se mueva usando tiempos. Es la forma más rápida de empezar.

⏱️
Autónomo por tiempos

Le decimos al robot: "avanza a 0.5 de potencia durante 2 segundos, luego gira a 0.3 durante 1 segundo, luego detente". Es simple y funciona para empezar.

AutonomoPorTiempos.java
@Autonomous(name = "AutonomoPorTiempos") public class AutonomoPorTiempos extends OpMode { private DcMotor leftFront, rightFront, leftBack, rightBack; private ElapsedTime timer = new ElapsedTime(); @Override public void init() { leftFront = hardwareMap.get(DcMotor.class, "leftFront"); rightFront = hardwareMap.get(DcMotor.class, "rightFront"); leftBack = hardwareMap.get(DcMotor.class, "leftBack"); rightBack = hardwareMap.get(DcMotor.class, "rightBack"); leftFront.setDirection(DcMotor.Direction.REVERSE); leftBack.setDirection(DcMotor.Direction.REVERSE); } @Override public void loop() { waitForStart(); // Espera START // Fase 1: Avanzar 2 segundos timer.reset(); while (opModeIsActive() && timer.seconds() < 2.0) { setMotors(0.5, 0.5, 0.5, 0.5); } // Fase 2: Girar a la derecha 1 segundo timer.reset(); while (opModeIsActive() && timer.seconds() < 1.0) { setMotors(0.5, -0.5, 0.5, -0.5); } // Fase 3: Detenerse setMotors(0, 0, 0, 0); } private void setMotors(double lf, double rf, double lb, double rb) { leftFront.setPower(lf); rightFront.setPower(rf); leftBack.setPower(lb); rightBack.setPower(rb); } }
🔜
Siguiente paso: Autónomo avanzado

Cuando domines el autónomo por tiempos, el siguiente paso es usar encoders para medir distancia real y sensores (IMU, color, distancia) para mayor precisión. Esto lo veremos en una guía futura.

Fundamentos de Programación

Estos conceptos aplican a cualquier lenguaje y te servirán no solo en FTC, sino en toda tu carrera como programador. Domínalos y serás imparable.

📦

Variables y Tipos de Datos

Una variable es un espacio en memoria donde guardas un valor. En Java, cada variable tiene un tipo.

Variables.java
int edad = 16; // Número entero double potencia = 0.75; // Número decimal boolean activo = true; // Verdadero/Falso String nombre = "Volkaniks"; // Texto
🔀

Condicionales (if / else)

Permiten que el robot tome decisiones según una condición.

Condicionales.java
if (distancia < 10) { // El robot está muy cerca: detenerse leftMotor.setPower(0); rightMotor.setPower(0); } else if (distancia < 30) { // Cerca pero no demasiado: ir lento leftMotor.setPower(0.3); rightMotor.setPower(0.3); } else { // Lejos: velocidad completa leftMotor.setPower(1.0); rightMotor.setPower(1.0); }
🔁

Bucles (while / for)

Repiten un bloque de código varias veces. Son esenciales para la lógica de los OpModes.

Bucles.java
// while: se repite mientras la condición sea verdadera while (opModeIsActive() && sensor.getDistance() > 10) { avanzar(0.5); } // for: se repite un número conocido de veces for (int i = 0; i < 4; i++) { moverBrazo(); sleep(500); }
⚙️

Funciones (Métodos)

Agrupan código que se repite. Hacen tu programa más limpio y reutilizable.

Funciones.java
// Definición de la función private void moverRobot(double potencia, int tiempoMs) { leftMotor.setPower(potencia); rightMotor.setPower(potencia); sleep(tiempoMs); leftMotor.setPower(0); rightMotor.setPower(0); } // Llamada a la función moverRobot(0.8, 1000);
🏗️

Programación Orientada a Objetos (POO)

En Java todo gira alrededor de clases y objetos. En FTC, cada OpMode es una clase que hereda de OpMode.

  • Clase: Un molde o plantilla. Ej: OpMode.
  • Objeto: Una instancia de la clase. Ej: tu MiTeleOp.
  • Herencia: Una clase hereda métodos de otra. Ej: extends OpMode.
  • Encapsulamiento: Usar private para proteger datos internos.
✨

Buenas Prácticas en FTC

  • Nombra bien tus variables: leftMotorPower es mejor que x.
  • Comenta tu código: Explica el "por qué", no el "qué".
  • Usa constantes: private static final double VELOCIDAD_MAX = 1.0;
  • Separa la lógica: Una función para leer gamepad, otra para mover motores.
  • Siempre actualiza la telemetría: telemetry.update() al final de cada ciclo.
  • Prueba incrementalmente: Un motor a la vez, una función a la vez.
